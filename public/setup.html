Ravnir

Set up Ravnir

A server that runs named bots, each with its own computer, model, memory, logins, and schedule. This guide assumes nothing except a machine and a terminal.

1. Install on a Linux server

Any Linux machine or VPS with Git works: Ubuntu 24.04 is what it is tested on. Give it 2 CPUs, 4 GB of RAM and 15 GB of disk. Three agents with their browsers open used 1.4 GB in our test, so 2 GB is the bare minimum.

git clone <your-fork-or-copy> ravnir
cd ravnir
./install.sh

The installer uses rootless Podman when it works for your user, then Docker, and offers to install Podman when there is neither. It builds the server image (a few minutes the first time), keeps everything in the ravnir-data volume, turns sign-in on with a generated password that it shows once, and starts Ravnir again after a reboot. It asks how you will reach it:

ChoiceWhat you get
Tailscale (recommended)A private https address only your own devices can open. Nothing is open to the internet. The phone needs the Tailscale app, signed in to the same account.
Your own domainhttps with automatic certificates from Caddy. Point the domain's DNS at the server and open ports 80 and 443 first: ./install.sh --access domain --domain ravnir.example.com
Only this computerRavnir listens on loopback only. Reach it from a laptop through an SSH tunnel. Phones cannot install the app this way.

Run ./install.sh again to update: your data, password and choices are kept. ./install.sh --reset-password makes a new password, ./install.sh doctor checks the install, and ./install.sh uninstall removes it (add --purge to delete the data too). The settings it writes are in ~/.config/ravnir/ravnir.env; lines you add there are kept and reach the server on its next start.

Agents run commands and a browser inside the container, as its own user. The container is the boundary: give the server only the access you want your agents to have.

2. Or run it on a Mac, or for development

Install Node 22 or newer, then:

git clone <your-fork-or-copy> ravnir
cd ravnir
npm install
npx playwright install chromium
RAVNIR_VAULT=local npm start
# open http://127.0.0.1:3847

RAVNIR_VAULT=local keeps the agents' shared notes in a git repo under data/vault. With OpenCode installed (npm install -g opencode-ai), the first-run setup can start it for you; or start Ravnir with RAVNIR_OPENCODE=managed. Ravnir then runs its own OpenCode on loopback with a password only it knows.

Port 3847 is the default; change it with RAVNIR_PORT. Ravnir refuses to listen on anything but loopback unless sign-in is on (RAVNIR_USER and RAVNIR_PASSWORD).

3. First run

The first time you open Ravnir, a short setup asks for your name and language, connects a model, makes your first agents (a chief of staff, a researcher, an engineer, and an inbox helper once Gmail is connected), optionally links your notes to a git repository, and shows a QR code to put the app on your phone. Leaving Grok Bot? The agents step links to Import from Grok Bot. You can open the setup again from Settings, Tools.

To put the app on a phone later, open Settings, Security, Add a device: it shows a one-time pairing code, good for 15 minutes, so you never type the password on the phone.

4. Models

Ravnir does not include a model. Through OpenCode it can use the providers you sign in to in Settings, Models: a ChatGPT, GitHub Copilot or SuperGrok subscription by device code, or an API key for any of OpenCode's providers. OpenCode also offers a few free models that need no account; setup picks the one whose provider keeps the least of your data, from what OpenCode's docs say. They can be slow or rate limited.

Any OpenAI-compatible server works too: add it in Settings, Models.

ServerBase URLNotes
OpenCoderun by RavnirRecommended. Many providers, tools, per-agent model.
Ollamahttp://127.0.0.1:11434/v1Local models.
LM Studiohttp://127.0.0.1:1234/v1Local models. Slow on some machines.
Hosted APIhttps://host/v1Paste the API key when you add it.

Model usage is billed by whoever runs the model. Ravnir adds no usage of its own and sends no telemetry. A scheduled job consumes model tokens each time it runs.

5. Your data

With the installer, everything lives in the ravnir-data volume; with npm start, in data/: state, each agent's workspace and browser profile, encrypted secrets, events, diffs, schedules, the notes vault and OpenCode's logins. Back it up. Do not commit it.

6. The computer

  • Screen is a real Chromium on the server. Click the image to click the page. Click a field, type in the strip below, press Enter. The browser profile is per bot, so cookies survive restarts.
  • Desktop is the whole X display on Linux. It shows the browser plus any native app the bot opens. Clicks and keys go through xdotool. Install Xvfb openbox xdotool scrot tesseract-ocr tesseract-ocr-spa on the server to use it.
  • Files is the bot's workspace. You can open and edit files. Saves produce diffs.
  • Shell runs commands on the server in the bot's workspace, with a persistent home for npm, pip, uv, cargo and bun installs. The bot can run commands too.
  • Logins stores site passwords encrypted with AES-256-GCM in data/secrets.enc. The password is never shown to the model. A bot can sign in with a saved login and only sees “signed in”.

Bots get two computer tools. computer_task reads the page DOM and offers the next clicks, keys and fields; desktop_task captures the X screen, reads it with Tesseract OCR and offers the labels it can click. Something picks each step: TypeSafe Jev in milliseconds when TYPESAFE_API_KEY is set, otherwise the quick model (RAVNIR_QUICK_URL) or the bot's own OpenAI-compatible model, otherwise the bot itself, one computer_step at a time. No key is required. Every step is saved under data/bots/<id>/computer/ and shown in the thread.

Try the built-in demo: open /demo/login in the bot's browser, sign in with any username and password, then reopen the computer. The session is still there.

7. Jobs

Jobs are cron entries that wake a bot. They run on the server when the browser is closed. Use standard five-field cron: minute hour day month weekday.

0 8 * * 1-5     every weekday at 08:00
*/30 * * * *    every 30 minutes
0 18 1 * *      the first of the month at 18:00

Add a job in the Jobs panel, or ask a bot to create one. Each job has an instruction, a next run, and a short run history. “Run now” tests it immediately.

8. MCP and connectors

The MCP panel adds a Model Context Protocol server to one bot. Use a local command for stdio, or a URL for remote HTTP. Ravnir connects, lists the tools, and gives them to the bot on its next turn. For OpenCode bots, the connector is also written into that bot's opencode.json so OpenCode can see it.

Secrets you enter for a connector are stored encrypted by Ravnir. OpenCode needs them in its own local config, so the bot's opencode.json is written with mode 600. Treat the workspace as private.

9. Running it on a VPS by hand

The installer covers this. Without it, do not expose the port directly: the app controls a browser and a shell. Keep it on loopback and reach it through an SSH tunnel, Tailscale (tailscale serve --bg --https=443 http://127.0.0.1:3847) or a reverse proxy with TLS, with sign-in on:

RAVNIR_USER=you RAVNIR_PASSWORD='a-long-password' \
RAVNIR_PUBLIC_URL=https://ravnir.example.com npm start

Keep the process alive with systemd, launchd, pm2, or tmux. Agents only stay on while the Ravnir process is running.

Make master.key and secrets.enc part of your backup, and keep them private. Lose the key and the saved logins are unrecoverable. Leak it and they are exposed.

10. Check it

./install.sh doctor    # with the installer
npm run doctor         # with npm start

It checks the data folder and disk, sign-in, that Chromium starts, the desktop tools, OpenCode, that a model is connected, the notes vault and phone notifications, and exits with an error when something required fails. The report names no host, address or person, so you can paste it into an issue.
